# Brain Tumor Detection — Backend API (Phase 2)

FastAPI service that wraps the Phase 1 `ml/predict.py` model behind a REST
API: upload an MRI slice, get back tumor location, confidence, area %, an
annotated image, and a downloadable PDF report.

**Verified in this sandbox:** the app imports cleanly, all routes register
correctly (confirmed via FastAPI's route table — see list below), `config.py`/
`db.py`/`schemas.py` were smoke-tested with real imports. **Not verified
here:** an actual `/api/detect` call end-to-end, because that needs
`torch`+`ultralytics` installed and a trained checkpoint, and this sandbox
ran out of disk space installing those (same limitation noted in
`ml/README.md`). Run the smoke test below on your own machine before trusting
it in production.

## Depends on Phase 1

This service imports `predict.run_inference()` / `annotate_image()` /
`write_pdf_report()` directly from the sibling `ml/` project rather than
duplicating that logic — so `ml/` and `backend/` need to sit side by side:

```
brain-tumor-detection/
├── ml/          # Phase 1
└── backend/     # this
```

## Setup

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# edit .env: point APP_MODEL_WEIGHTS at your trained checkpoint
# (ml/runs/train/tumor_yolo11/weights/best.pt) once you have one —
# it defaults to a stock, non-tumor-tuned yolo11n.pt so the API still boots.
```

## Run

```bash
uvicorn app.main:app --reload --port 8000
```

Interactive docs: http://localhost:8000/docs (auto-generated by FastAPI —
covers most of what API_DOCUMENTATION.md would otherwise restate by hand).

## Smoke test (do this first)

```bash
curl http://localhost:8000/api/health

curl -F "file=@/path/to/an_mri_image.jpg" http://localhost:8000/api/detect
```

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/detect` | Upload an image, run detection, persist + return the result |
| GET | `/api/history` | Paginated list of past detections (`?limit=&offset=`) |
| GET | `/api/history/{id}` | Full detail for one past detection |
| DELETE | `/api/history/{id}` | Delete a past detection + its record |
| GET | `/api/image/{id}/annotated` | The annotated image for a detection |
| GET | `/api/report/{id}` | The PDF report for a detection |
| GET | `/api/model/info` | Currently loaded model's weights path, classes, thresholds |
| GET | `/api/health` | Liveness + whether the model finished loading |

`/api/history` with two ids fetched via `/api/history/{id}` is what a
frontend "Compare Images" view would call — no separate compare endpoint
needed, it's just two detail fetches.

## Storage

- SQLite by default (`./storage/app.db`) — zero config, single file, fine for
  a single-instance deployment. Swap `APP_DATABASE_URL` for a Postgres URL in
  `.env` if you need concurrent multi-writer access; no code changes required
  elsewhere (SQLModel handles both the same way).
- Uploaded images, annotated images, and JSON/PDF reports are written to
  `./storage/{uploads,annotated,reports}/` — local filesystem, no S3/cloud
  storage dependency. Point `APP_STORAGE_DIR` elsewhere (e.g. a mounted
  volume) for Docker deployments.
